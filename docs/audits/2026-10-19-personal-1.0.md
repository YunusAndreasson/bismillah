# Personal 1.0 audit (2026-10-19)

The final accessibility, contrast, offline and performance audit of PLAN.md Phase 6, with the package's size. Everything here was run on the author's machine (Intel i7-7820HQ, 4 cores and 8 threads, 32 GB, Arch Linux, WebKitGTK 2.54.1), on the commit that records it. Real-app runs are headless (`scripts/headless.sh`: Xvfb without a GPU, so WebKit renders in software, and no window focus).

Each section says what was checked, how, what it found, and what changed because of it.

## Accessibility

**How:** `pnpm a11y` (new) reads the accessibility tree that Orca gets over AT-SPI, from a private accessibility bus inside the harness, in eleven screens and states: writing (the specimen), the guide, Settings, About, the library, quick open, the command palette, *Rename…*, the suggestions, a save that failed, and the first screen. It fails on a control (button, switch, radio, field, list, tree or menu item, link) or dialog without a name, and checks what each state must offer: Settings' four sections as level-2 headings and its radio groups with one checked; the library as one named tree, its folders expandable and the open file selected; quick open and the palette as named dialogs listing options, one selected; the suggestions as a named menu with *Add to dictionary*; a failed save as an alert; the first screen's three choices. The native menu bar's items are checked for names too. The e2e suites drive every action from the keyboard, and the contrast tests are below.

**Found and fixed:**

| Problem | Fix |
|---|---|
| The writing surface had no accessible name: a screen reader said only "edit text" | It is named by the open file's name (`letter.md`), and follows a rename |
| Settings' and About's section headings reached screen readers as "APPEARANCE", "WRITING"…: WebKit hands CSS's capitals to AT-SPI | Each heading carries its name as written (`aria-label`); it still looks the same |

**Result:** after the fixes, no problems in any of the eleven states (`pnpm a11y`: 105 named controls checked).

**Also checked:**
- *Show in file manager* appears three times in Settings; each button is described by its setting's heading (Library folder, Your settings, Unsaved text), so the three can be told apart.
- New commands (*Open link*, *Guide*) are in the palette and the menus, and *Open link* opens the link at the caret, so Ctrl+click has a keyboard equivalent.
- Reduced motion: `app.css` and Settings remove their transitions under `prefers-reduced-motion`. WebKitGTK has no forced-colours mode; *High contrast* (Settings › Appearance) is bismillah's own.
- 200 % zoom: the desktop's scale doubles CSS pixels, so a 1280 px window at 200 % lays out as the 640 px screenshots do, which the specimen, Settings and the guide were checked at.

**Not automated:** what Orca says aloud (speech, and its announcing of live regions), typing through fcitx5, and the focus highlight in menus, which headless runs can't show. They stay in PLAN.md's manual checks.

## Contrast

**How:** `src/styles/tokens.test.ts` checks every semantic pair of DESIGN.md §9.4 in light and dark, high contrast at 7:1 for every text pair, Zuhd mode's faint text, and text on code's translucent ground with a selection behind it; `themes.rs` holds the built-in themes (Sepia, Slate) to no problems, prose above 7:1. Both run in `pnpm verify`.

**Result:** every pair passes. The new interface text (the link tooltip's *Ctrl+click to open*, the folder buttons) uses `text-secondary` and `text-primary` on `surface-editor`, pairs the tests already hold at 4.5:1 or more.

## Offline

**How, at run time:** `pnpm test:offline` runs the whole e2e suite (links and the guide included) in a network namespace with only loopback, under `strace -f` over every process the app starts (WebKit's web and network processes too), and fails on any connection that isn't loopback.

**Result:** all 18 suites (182 tests) pass with no network; 186 socket calls, every one to loopback (the test tooling's WebDriver connection).

**How, in what is built:**
- **Rust dependencies** (`cargo tree` for the Linux target): no HTTP, TLS, DNS, WebSocket or download crate. `tokio` is built with `rt`, `rt-multi-thread`, `fs`, `sync`, `io-util` and `bytes`, not `net`; `mio` comes only from `notify`, for inotify. `url`, added for links, only parses. `cargo deny check` (bans, licences, advisories) passes.
- **npm dependencies:** `pnpm audit` finds no known vulnerabilities; the shipped packages are CodeMirror, Lezer, Bits UI, markdown-it, DOMPurify and Tauri's API.
- **The release binary's imports:** `socket`, `connect`, `bind`, `listen`, `accept4`, `sendmsg` and `socketpair`, all serving Unix-domain sockets: the single-instance socket in `$XDG_RUNTIME_DIR`, D-Bus (GTK and the file dialogs) and the display connection. No name resolution (`getaddrinfo`) is imported.
- **WebKit** always starts its network process; the CSP (`connect-src` only the IPC origins, no remote images or fonts), the navigation guard (no navigation away from the app, no new windows) and the strace run above keep it idle.
- **Links** (new): handed to the desktop only on an explicit Ctrl+click or *Open link*, only `https:`, `http:` and `mailto:` (checked in Rust, `links.rs`), and never under the test harness, where they are recorded instead. bismillah makes no request; the browser does.

## Performance

`pnpm perf` (new) measures ARCHITECTURE.md §14's budgets in the release build.

Release build, headless (no GPU: WebKit composites in software), on a quiet machine; launches are warm medians of nine after a first, cold one.

| Budget (ARCHITECTURE.md §14) | Measured | Verdict |
|---|---|---|
| Launch to an editable caret under 400 ms | 524 ms (cold 730 ms), a short document; 521 ms with 50,000 words. Before the page loads (GTK, the window, WebKit's processes) 274 ms; its script 32 ms; the start (settings, the document from Rust, the first fonts, the editor) 214 ms. A later run, with another busy process on the machine: 588 ms with no library, 586 ms with a remembered library of 1,000 files | **Not met.** Was 716 ms before this phase; a library no longer adds to it |
| No dropped frames while typing in a 1 MB document | Key to painted frame, at the median and p95: a short document 10 / 19 ms; the 1 MB book (175,000 words) in prose 19 / 37 ms, on a line with code 24 / 42 ms. Frames longer than two refresh intervals while typing: 0.8 %, 4.4 %, 9 % | **Not quite met at 1 MB**; met in a short document. Was about 960 ms a key |
| Lint results within 500 ms of a typing pause | Measured in Phase 3 (8–25 ms per edited paragraph at the median, under 165 ms at p95, on 50,000 words); checking's code is unchanged since | Met |
| No CPU use when idle | 30 ms of CPU in a quiet minute across the three processes, with a library of 1,000 files open (0.05 %) | Met, once the watcher was fixed: it was 5 % of a core with that library |

Memory, recorded: 755 MiB resident with a short document open and checked and a library of 1,000 files (bismillah 479, WebKit's web process 214, its network process 62), 915 MiB with the 1 MB book open.

What limits the two budgets not met:
- **Launch:** over half is GTK and WebKit starting their processes, before bismillah's page loads; the rest was cut by a quarter (above). Under the harness WebKit has no GPU; the desktop may be faster or slower, so a launch on the live session is worth timing by hand.
- **Typing in 1 MB:** what remains is CodeMirror's Markdown parser re-reading the block structure on each edit: Lezer's incremental parse walks every top-level block (`takeNodes`, `balanceRange`), about 6 ms in V8 and 15 ms in WebKit's JavaScript engine for this book's 7,200 blocks. bismillah's own live preview now adds nothing measurable in prose. A long book written as one chapter per file, as the library encourages, stays far below it.

The binary carries everything it needs: the fonts (5.6 MiB, all sixteen faces), the Arabic dictionary (7 MiB), Harper's English dictionary and model, the guide and the frontend. ## What changed because of the audit

- **Typing in a long document.** Drawn tables were drawn again on every key, all of them: in a 1 MB book a key took about a second. Grids are now kept by their text, and an edit that can't change them (typing in the revealed block, away from tables, links, images and line starts) only moves them, as it moves images and keeps the link definitions (`inlineEdit`, unit-tested with its fallbacks).
- **Launch.** Only the faces the first screen uses are loaded before the text shows (were all sixteen, 5.6 MB); the fonts load while Rust opens the document; the native menu is built after the text is editable; and the Markdown language no longer brings the HTML, CSS and JavaScript grammars (the script went from 917 KB to 732 KB).
- **An open library kept the app busy.** `notify` reports files and folders being opened, not only changed, and the watcher counted those: the library's own listing opens every folder, so each listing set off the next, for as long as a library was open (Phase 2's code; 5 % of a core with 1,000 files, 60 % with this repository as the library, as the author's own instance had it). Reads are no longer changes (`watch.rs`, with a test that fails without the fix), and in the library only Markdown files and folders count, so a build writing thousands of other files there costs nothing either. The first idle measurement missed it because it ran without a library; `pnpm perf` now measures launch and idle with one.
- **Launch with a library.** Listing and watching the remembered library ran on the main thread before the window existed (50 ms for 1,000 files); it now runs on a thread of its own while WebKit starts, and whatever needs the library waits for it.
- **Punctuation wrapped away from hidden marks.** CodeMirror puts a zero-width image beside each hidden mark so the caret can stand there, and WebKit may break a line beside an image, so a `)` or `;` after hidden code or emphasis marks could start the next line (174 such breaks across the widths tested). Out of the line's flow (`position: absolute`) the image is no longer a break, and the caret, click and selection spikes and every visual baseline pass unchanged.
- **Fonts after the first screen.** The faces the first screen doesn't use load once the window is ready, so the first italic or Qur'anic run never waits, invisible, for its font.
- **Accessibility.** The writing surface's name and the headings' names, above.
