# UI review — 2026-10-19

Requested goal: drive the app as a principal UI engineer and fix obvious
shortcomings. This pass reviews the existing desktop product against DESIGN.md,
using the actual Tauri/WebKitGTK application, scratch files, private settings and
trash, and a private Xvfb display. It follows the earlier exploratory QA audit;
the fixes below are additional work.

## Findings and fixes

### Maximum-length filenames could open but could not save

The extended UI recovery test opened a legal 255-byte filename. After clearing an
injected disk-full fault, Try again still failed with `InvalidFilename`. The atomic
writer appended its temporary suffix to the complete original basename, exceeding
the filesystem's component limit.

Temporary names now use a bounded local path identifier, process id and counter in
the same directory. Durable write ordering, permissions and byte preservation are
unchanged. Stale-temp cleanup supports both the new pattern and the old pattern,
and requires a valid numeric process/counter suffix. Rust regressions save ASCII
and Arabic names at 255 bytes, inject a rename-stage failure, check the untouched
original and absence of leftovers, retry, and verify exact vocalised Arabic bytes.
Another regression checks interrupted-save cleanup leaves another document's
temporary and malformed names intact. The real UI test retries successfully and
reads the saved file back.

### Long filenames broke recovery notice layout

At 480 × 360, an unbroken 180-character name made the page 1722 pixels wide. Even
at 1280 pixels the message spilled outside its notice. The recovery region now
uses a constrained grid track, and its message can wrap unbroken text. Tests cover
Latin, Arabic and a 255-byte name in both themes, at widths 480, 640 and 1280.
They check the entire message, window bounds, recovery controls, and a real click
on Try again followed by an exact-byte disk check. This follows DESIGN.md §§6, 12, 14.

### Rename controls fell below a short window

With the same long filename, Rename's buttons reached below 460 pixels in a
360-pixel window. The dialog had no scrolling bound. The title is now compact,
retains its complete accessible text and has a full-text native tooltip. The dialog
is bounded and scrollable, and short windows use the available height. Validation
brings its explanation into view. The regression checks the field, inline error and
both buttons are visible, then tabs to Cancel and verifies that nothing was renamed
or rewritten. DESIGN.md §§6, 13, 14, 16.

### Settings could hide a requested section heading

At the minimum window width, the navigation wraps. Its sticky header ended at
138 pixels while Files & privacy's heading was placed at 116–133 pixels: completely
covered. The scroll container now clears the measured header height, which tracks
resizing, plus token-based spacing. Section navigation measures immediately as well
so opening directly at Files & privacy works on the first frame. Tests exercise all
four section links at 480, 640 and 1280 pixels, checking heading focus and visibility.
DESIGN.md §§6, 7, 16.

### Overlay-library shortcuts and focus differed from the docked library

The global shortcut guard treated the overlay library like a settings dialog and
blocked commands inside it, including its own toggle and F2. The guard now recognises
the library as a navigation surface while keeping commands behind other dialogs
inert. Opening or creating a document closes the overlay. A document-choice focus
request prevents the overlay from restoring focus to its opening button, and hands
focus to the editor after the focus trap is gone. Ordinary dismissals retain their
normal focus restoration. Cancelling a nested Rename prompt likewise waits for its
inert layer to be removed before restoring the overlay tree row. Opening a document also waits for its writing surface to
be rendered before focusing it.

The Rename input takes focus after its nested focus scope is installed; focusing
it during DOM mount let the underlying library trap take it back. The regression rebinds the library shortcut, opens the overlay, uses F2 and Cancel,
and hides it with the rebound shortcut. Another flow opens the panel with its button,
uses Open, then opens it by keyboard and uses New file. It sends a real X keyboard
event to type into the newly opened document without manually focusing the editor,
then verifies the exact saved text. DESIGN.md §§6, 7, 13.

### Native menus advertised unavailable actions

Save and document-copy actions remained enabled on the welcome screen even though
the registry refused to run them. The native menu now applies registry availability
and refreshes before Alt/F10 reveals it. Undo and Redo also require editable history,
so their menu and palette entries reflect the current document.

The test focuses the private app window and uses native X events for F10 and Escape.
It reads `isEnabled()` from the installed Tauri menu items, checks welcome/open-file
states, types, undoes, and checks Undo/Redo transition. This is native state, not a
test of a cached frontend expectation. DESIGN.md §§6, 13.

### Cramped status information lacked useful hints

Ellipsised filenames now expose their full name on hover. The Library button's
tooltip shows its current shortcut, and its accessible shortcut follows the same
binding instead of always advertising Ctrl+Backslash. A removed binding removes the
accessible shortcut. The real-app test edits the private `keybindings.toml`, waits
for its watcher, inspects both hints, exercises the new key and removes it.
DESIGN.md §§6, 12, 13, 16.

### About opened with invisible keyboard focus

About deliberately opens at the start of its text and focuses Close without scrolling.
At the minimum window height that button was below the long credits list, so the
focused control was off-screen. Close now stays in an opaque sticky footer while
the content scrolls. The regression opens at the start, checks that Close has focus
and is visible, and dismisses with Escape in both themes at widths 480 and 1280.
DESIGN.md §§6, 13, 16.

### Spelling suggestions extended below a short window

At 480 × 360, the spelling menu extended from y=196 to y=500, hiding Ignore and
Add to dictionary. Its scrollable height now follows the available space measured
by Bits UI. The regression opens suggestions in both themes, checks the entire menu
is within the window, presses End and checks that Add to dictionary has visible
focus, then dismisses without changing the document. DESIGN.md §§11, 13, 16.

### Late spelling responses could reopen a dismissed menu

The full checking suite exposed a race while moving through issues with F7: Escape
could close the current menu while a spelling response for the next issue was still
pending. That response reopened the popup. Closing or changing documents now
invalidates pending openings. Two deterministic unit tests hold the response,
dismiss the menu or change documents, release it, and verify that no menu opens and
source text remains unchanged. The existing real-app F7 / Shift-F7 / Escape flow
also checks this behaviour.

### Offline glyph checks needed a larger tracing budget

The complete offline run reached all twenty specs. One Arabic per-glyph click case
exceeded its ordinary 60-second case budget under strace; the failure was a timeout,
not a caret-position mismatch. These long cases now have a 120-second budget. All
assertions remain in place. This is a test-harness correction, not an editor change.
The final traced rerun below includes that full spec plus checking and the new UI
regressions. The first full trace had 276 network calls, all loopback, with no
external attempts; its expected read-only-permission fixture skips as root.
