# Search: one palette for files, commands and settings (2026-10-29)

The author found the three tabs at the bottom left (Files · Commands · Settings,
ADR-0016) non-standard and asked for one palette on `Ctrl+K`, as in Notion, Linear,
Raycast and VS Code, keeping `Ctrl+P`, `Ctrl+Shift+P` and `Ctrl+,` as ways into it and
one quiet *Search* in the status line. Recorded as
[ADR-0018](../decisions/0018-one-palette.md); DESIGN.md §6, §7, §9.4, §12, §13 and §16,
the guide, ARCHITECTURE.md and PLAN.md are rewritten to match.

Three days earlier the author had found *Find anything*, a single palette, too crowded,
and had just asked that no row change height. The design was planned against both,
with a review of the leading apps and an adversarial design review before building.

## What changed

| Area | Three panels (ADR-0016) | Search (ADR-0018) |
|---|---|---|
| Where | Rising from the bottom-start corner, as tall as the window | Centred near the top, 42rem wide, one fixed height |
| Ways in | Files, Commands, Settings in the status line; their shortcuts; `Shift Shift` for the last one | *Search* in the status line, `Ctrl+K`, `Shift Shift`; `Ctrl+P` / `Ctrl+Shift+P` / `Ctrl+,` open it narrowed |
| Moving between | Tabs at the foot, counts on them; `Tab` to the next panel | A scope at the start of the field (× or `Backspace` widens); `Tab` through everything, files, commands, settings, keeping the query and the highlighted row |
| Nothing typed | Each panel's full list | Everything: recent files only, without the open one. Narrowed: the old lists |
| A query | One ranked list per panel | Everything: Files, Commands, Settings in fixed sections, a few of each, totals on cut headings |
| Footer | Key line, *Tab next panel*, tabs, *Close* | Two-line description (a file's folder too), key line ending *Tab ‹next scope› · Esc close* |
| `← →` | Change a choice in Settings | The same in Settings; elsewhere they move the caret |
| File keys | In Files | On a highlighted file or folder, in any scope |

Removed: the tabs and their counts, the Close button, the last-panel memory
(`lastPanel`), `counts()`, and the panel buttons' alignment over the status line.

## Decisions taken in the design review

- **Fixed height, not "fits its content":** a top-anchored palette that shrank to its
  rows would move its footer on every keystroke, which is what the author had just asked
  to avoid.
- **Fixed section order, not ordering by match quality:** sections that swap places as
  you type move the row under the eye. Instead, a *noise floor*: scattered-letter
  matches are dropped whenever any row matches as a run of letters
  (`fuzzy.ts` `fileTier`/`commandTier`), so "theme" lists the Theme command and setting,
  not file names that happen to contain t…h…e…m…e.
- **Each switch once:** *Zuhd mode*, *Check spelling* and the other switches are both
  commands and settings; everything lists them once, as the command with its shortcut
  (`SettingEntry.command`).
- **No "Show all N…" rows:** a cut section's heading gives its total and narrows on a
  click; `Tab` and the scope shortcuts already narrow by keyboard.
- **`← →` only in Settings:** in everything, a highlighted setting under the caret would
  otherwise change while the writer corrects a typo. Right-to-left queries keep the
  arrows for the caret too.
- **No Close button:** no leading palette has one; `Esc`, a click outside and *Search*
  in the status line close it, and the key line says *Esc close*.
- **Commands from the status line run in the text:** *Go to line…* opened from Search
  after a click on *Search* now has the editor's focus.
- **The open file is left out of everything's Recent**, so `Ctrl+K Enter` returns to
  the previous file.
- **Ctrl+K belongs to Search.** bismillah has no link command (ADR-0015).

Found while building: an Arabic query turned the field's logical padding round and
opened a gap after the scope; the padding now sits on the field's container. A command
without a shortcut left an empty slot after *On*. The guide's Find section said
"search" for the search in the document; it now says *Find*, and *Search* means only
the palette (DESIGN.md §13).

## Design review (DESIGN.md §18)

Checked in the real app (`pnpm app:shot`) at 640 (and 640 by 360), 1280 and 2560, light
and dark, with Arabic folder, file and query.

1. **The important content is apparent:** the field, then the highlighted row; section
   headings are small and quiet, values sit at the row's end in `text-secondary`.
2. **The current scope, file and action:** the scope sits in the field; the open file
   is weight 600; the description line says where a file is or what a command does,
   and the key line what `Enter` and `Tab` do.
3. **Grouping:** fixed sections by kind; an opened setting continues its row under the
   same accent edge; dependent settings indented under their parent.
4. **Keyboard and semantics match:** one tab stop (the field), options with
   `aria-selected`, groups labelled by their headings, the dialog named by its scope, a
   polite status for scope changes and *No results*; `pnpm a11y` passes.
5. **Widths, themes, RTL, short windows:** one height everywhere; below ~24rem of
   height the description takes one line and the key line drops its end; below ~30rem
   of width the margins narrow to 8px; Arabic names are isolated with `<bdi>` and an
   Arabic query stays at the field's start.
