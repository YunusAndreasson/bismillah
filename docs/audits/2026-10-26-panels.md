# Files, Commands and Settings (2026-10-26)

The author found Find anything (`Shift Shift`) too crowded: a 60rem panel with the
library tree, recent files, the main commands, settings, four scope buttons and a
long key hint. They asked for three panels, **Files, Commands and Settings**, opened
from the bottom left, with no folder tree anywhere, clean panels that use the window
well, and deliberate use of Tab and the arrows. Their choices: the tree goes
everywhere (docked, overlay and panel); the Settings panel replaces the Settings
dialog; the panels rise from the bottom left; `Shift Shift` reopens the last panel.
Recorded as [ADR-0016](../decisions/0016-three-panels.md); DESIGN.md §6, §7, §9.4,
§12, §13 and §16 are rewritten to match.

## What changed

| Area | Before | Now |
|---|---|---|
| Status line | *Library* toggle | *Files · Commands · Settings*, quiet, each with its shortcut |
| Library | Tree docked beside the text, an overlay in narrow windows, a tree inside Find anything | Files panel: Recent, then All files with their folders; folders when searched; `Folder/` narrows |
| File actions | On the tree's focused row | On Files' highlighted row: `F2`, `Delete` (once nothing follows the caret), `Ctrl+N`, `Ctrl+Shift+N` |
| Commands | Find anything's main commands, or the palette scope | Commands panel, grouped by menu; switches change in place |
| Settings | Dialog in four sections with section links | Settings panel: one row per setting, `←` `→` change, `Enter` opens in place |
| Moving | Scope buttons, `Tab` into the tree | `Tab`/`Shift+Tab` between panels with the query kept, counts on the tabs |
| `Shift Shift` | Everything, or closed from Everything | The last panel, or closed |

Removed: `LibraryTree.svelte`, `LibraryPanel.svelte`, `Picker.svelte`,
`SettingsDialog.svelte`, `layout.ts`, the tree keyboard model, `view.toggleLibrary`
(`Mod-\`), the library offset, and Rust's remembered *library shown*
(`library_remember_open`; old `state.json` files still load).

## Hierarchy and space

- The panel rises from the bottom-start corner, up to 46rem by 60rem, as tall as the
  window allows short of a 48px margin, so a long list shows 20 or more rows at 1280
  by 900. At 640px and below it takes the window's width.
- Its tabs sit exactly over the status line's names (checked in
  `panels.e2e.ts` to within 1.5px), so the status line seems to lift the panel. The
  current tab is marked by colour and an underline, never weight, so no name moves.
- One line per row; values (folder, shortcut, On/Off, choice) aligned at the end in
  `text-secondary`; a description or hint only under the highlighted row. Group
  headings only with nothing typed.
- One line of key hints, changing with the highlighted row, and *Tab next panel · Esc
  close* at its end. A quiet *Close* sits at the end of the tabs.

## Keys

| Key | Does |
|---|---|
| typing | filters; focus stays in the search field (`aria-activedescendant`) |
| `↑` `↓`, `Page Up` `Page Down` | move the highlight, round the list; a page at a time |
| `Enter` | open, run, change a switch, open a row in place, or narrow to a folder |
| `Tab`, `Shift+Tab` | next or previous panel, query kept, counts on the tabs |
| `←` `→` | change a highlighted choice or size, while the caret is at the end |
| `Esc` | close an opened row, then the panel |
| `Ctrl+P`, `Ctrl+Shift+P`, `Ctrl+,` | open, switch to, or (its own) close a panel |

Found while building: WebKitGTK reports `Shift+Tab` (ISO_Left_Tab) as `key:
"Unidentified"` with `code: "Tab"`, so the panel reads the code too.

## Design review (DESIGN.md §18)

Checked in the real app (`pnpm app:shot`) at 640, 1280, 1920 and 2560 in both
themes, at 200% text and in high contrast, with Arabic file and folder names.

1. **The important content is apparent:** the search field, then the highlighted
   row; group headings are small and quiet, values sit at the row's end in
   `text-secondary`.
2. **The current file, panel and action:** the open document's name is weight 600 in
   Files, the current panel is the underlined tab, and the key line says what `Enter`
   does on the highlighted row.
3. **Grouping:** an opened setting continues its row under the same accent edge and
   fill; the tabs repeat the status line's names in place.
4. **Keyboard and semantics match:** one tab stop (the field), options with
   `aria-selected`, tabs with the current one selected; `pnpm a11y` passes.
5. **Widths, themes, RTL, enlarged text:** full width at 640, 46rem from there up;
   Arabic names are isolated with `<bdi>` and the field follows the query's direction.

Found and fixed during the review:
- A recent file appeared under Recent and All files with the same value, so both rows
  were highlighted and the arrows stalled on them; Recent rows now have their own
  value (`recent:`).
- Recent files never updated after opening a file, because the listing was only sent
  again when something on disk changed; Files now asks for it after every open.
- The key line wrapped to two lines on a file row; it is now a one-line legend
  (*Enter open · F2 rename · Delete move to the trash*).

Note for the author: at 2560 the panel stays 46rem wide, which keeps rows readable;
the window's other half stays the writing.

## Follow-up (2026-10-29)

A review of the three panels in the real app (`pnpm app:shot --open …`, at 640 and
1280, both themes, rows opened in place) found that the keys didn't always do what the
key line said, and a few slips in grouping and alignment:

| Found | Now |
|---|---|
| Enter in an opened *Text size* or *Line height* did nothing, though the key line and the guide said it closed the row | Enter on the stepper closes it; a focused − or + still presses |
| An opened row's key line always said *Enter or Esc done*, which is wrong for *Font name* (Enter uses the name) and for buttons | Each kind says its own keys: *← → change · Backspace reset · Enter or Esc done*, *Enter use this name · Esc done*, *Esc done* |
| *Show in Settings* or the test hook could “open” a note, switch or About row, which has nothing under it | Only rows that hold something open (`opensInPlace`) |
| An opened choice or size showed its value twice, at the row's end and in its control | The row's end value is hidden while it is open |
| Keyboard shortcuts' button almost touched its sentence | Its sentence, button and problems keep the opened rows' 12px gap |
| Row text sat 3px inside the search field, the headings and the key line, because of the highlight's edge | One reading edge |
| *Focus on* and *Other text* read as settings of their own; *Other text · Quiet* meant nothing alone | Indented under *Zuhd mode* (and *Font name* under *Writing font*) with nothing typed; *Other text*'s hint names Zuhd mode |
| *Enter every choice*, *Enter more* | *Enter all choices*, *Enter open* |
| The status line's reading time kept its spare room between the last dot and the time | The spare room falls at the window's edge |

Evidence: `src/core/settingEntries.test.ts` (dependent rows follow their parent, which
rows open) and two new cases in `tests/e2e/panels.e2e.ts` (stepping, resetting and
closing a size by keyboard; an opened choice's key line; a note asked to open).
